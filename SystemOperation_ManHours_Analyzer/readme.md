# 運用業務分析ツール
## 背景
とあるシステムの運用業務を外部ベンダーに委託しています。
運用工数を見える化し、やらなくても良い作業を削減するために、M365のListsを利用して作業毎のステータスや工数の管理を行っています。
このデータを可視化して、今後の運用費用計画を立てたいと考えています。

## 目的
- 工数消化のペース把握
    - 急激に工数を消化していないか把握し、オーバーペース気味なら抑えるなどの措置検討材料
- 現時点での消化状況(工数、パーセンテージ)
    - 期末までの残り工数の把握(余裕 or 厳しい)
    - オーバーペース気味なら抑えるなどの措置検討材料
- 作業割合の把握
    - 改善実施を行うべき作業の特定
    - 新規に出てきた作業の割合の把握
- 週毎の工数使用状況の把握
    - 車種適用日程との整合性理解
- 予実剥離の把握
    - 予定工数の精度が上がっているかの確認

## 機能
- csvファイルは画面上部に配置されたドロップ可能領域にドラッグ＆ドロップすることでアプリへ投入する
- 実績工数の合計をグラフで表示
    - グラフは棒グラフとし、縦軸は実績工数、横軸は期間(クオーター,週,日)とする。
    - 個々のグラフについて、全体が1画面に収まるようにし、横スクロールしなくてもグラフ全体が確認できるようにする。(以降のグラフについても同仕様とする)
    - グラフの横軸ラベルは斜め45度(行末が右上に上がる形とし、右上が棒グラフの根本に位置するように)にして、多くのラベルを表示できるようにする。
    - 期間の種類毎にグラフを作成する。期間の種類は以下のとおり。
        - クオーター毎
        - 週次
        - 日次
- 作業種類毎の実績工数と割合をグラフで表示
    - グラフは棒グラフとし、縦軸は実績工数、横軸は期間(クオーター,週,日)
    - 期間の種類毎にグラフを作成する。期間の種類は以下のとおり。
        - 全期間
        - クオーター毎
        - 週次
        - 日次
    - 基準日は[着手予定日]列を参照する
    - 週次の横軸は、週の開始日を表示する
    - クオーターは[実施時期]列を参照する
    - 作業時間は[実績工数]を参照する
    - 作業種類は[定常業務No]と[気付き番号]を参照する
    - 凡例は以下の順番とする。
        - 定常業務No
        - 気付き番号
- 時期毎の作業発生回数をグラフで表示（日毎の件数、作業時間）
    - グラフは棒グラフとし、縦軸は作業発生回数、横軸は期間(クオーター,週,日)
    - 期間の種類毎にグラフを作成する。期間の種類は以下のとおり。
        - 全期間
        - クオーター毎
        - 週次
        - 日次
    - 作業発生回数はアイテム数をカウントする
- 期間内の定常業務No,気づき番号毎の実績工数を1つのグラフで表示
    - グラフは棒グラフとし、縦軸は実績工数、横軸は定常業務No または気づき番号とする
    - 横軸は、実績工数が多い順に左から配置する
- 指定期間内の残り工数計算において、[計画開始日]、[計画終了日]、[消化状況の基準日]、[期間予算（時間）]を入力可能とする。
- 上記の[消化状況の基準日]以外は変更時に localStorage へ記憶し、画面描画時に前回の入力値を復元する
- [消化状況の基準日] は、今日の日付を初期値として設定
- CSVファイルのカラム名は変更が容易なように、プログラムの冒頭で定数として定義する。
- 日次グラフ以外のグラフの横軸は間引きせず全項目を表示する
- 各グラフの集計値リスト内容をCVSダウンロード可能。
- ブラウザの横幅に合わせて、グラフの横幅を追従する

## CSVファイルのカラム仕様
カラム名と、値の種類は以下のとおり。
- ステータス
    - 申請中
    - 作業中
    - 取り下げ
    - 完了
- 作業名
    - 文字列
- 着手予定日
    - フォーマットは mm/dd/yyyy
- 予定工数
    - 小数点第一位まで
- 実績工数
    - 小数点第一位まで
- 定常業務No
    - 整数
- 気付き番号
    - 気づき番号＝不具合番号
    - 文字列(ex. 4-222)

## 実装時の制限
- HTML, CSS, JSで開発。
- WEBフロントエンドのみで動作するアプリとする。
- (廃止)グラフ描画はvis.jsを利用する。
- (廃止)vis.jsは、jsdelivr.com で公開されている最新版をCDN経由で参照する。
- (追加)グラフ描画ライブラリは chart.js を利用する。
- (追加)chart.jsは、jsdelivr.com で公開されている以下の最新版をCDN経由で参照する。
    - https://cdn.jsdelivr.net/npm/chart.js@4.5.1/dist/chart.umd.min.js

## コーディングの制約
- 容易に人がメンテナンス可能なコードを心がける。
- HTML, CSSは1つのファイルに, jsは別ファイルで作成する。
- 関数ヘッダをつけ、関数の処理概要、引数、戻り値の仕様がわかるようにする。
- 処理ブロック毎にコメントを入れる
- if, for, whileなどは { や } で改行する
- 全体で利用する変数は、プログラム先頭でまとめて宣言し、コメントをつける。
- クラス化した方がわかりやすい処理の塊はクラス化する。
