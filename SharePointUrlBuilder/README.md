# SharePoint URLビルダー

## 目的
- ある業務システム(SharePointベース)において、目的のデータに辿り着くまでに、いくつかの画面遷移及びドロップダウンからの属性選択を経る必要があり、非常に時間を要している。
- サイトやフィルタ条件を指定することでURLを生成し、一度の操作で目的のデータにアクセスできるようにする。

## 本アプリの動作環境
- Windows11 / Microsoft Edge

## 実装方法
- 外部ライブラリを使用しないHTML/CSS/JSで作成する
- 外部サーバとの通信は一切行わない

## 仕様
- アクセス先サイトを指定する属性として、以下の属性が選択可能。
    1. 部門
    1. リスト種類
- フィルタ条件として以下属性が指定可能。値は入力可能。
    1. 担当グループ
    1. 法規番号
    1. 要件区分番号
    1. 要件分類番号
- 部門を切り替えた場合、リスト種類・担当グループの選択肢を部門に所属しているグループへ切り替える。(関連付けはconfig.jsで定義)
- リスト種類を切り替えた場合、選択されたリスト種類で指定可能な属性へ切り替える。(config.jsで定義)
- 「01.アクセス条件」の領域は、選択項目数が多い場合にウィンドウ縦幅の半分まで広げる。
- 各条件の属性列は独立して縦スクロール可能とする
- 以下はconfig.jsでdict配列形式で定義する。
    - ベースURL
    - 各属性値の表示名、URLの一部として利用する内部ID
    - 各担当グループの所属部門
- config.jsで定義する属性は任意の数を定義できること
- 部門、リスト種類以外は[指定なし]を選択することが可能。
- ドロップダウンからの選択は避け、ボタンでの選択式とする。
- 選択可能な属性は縦に並べ、各属性群を画面左から右へ順番に選択できるようにする。
- アクセスする対象のビューはconfig.jsで指定がない場合は[全てのアイテム]とする。(AllItems.aspxを使用. listTypes.viewPage で複数指定可)
- 1属性のみソート指定可能とする。
- ソートのUIでの指定方法はトグルボタンとする。(降順→昇順→指定なし)
- 各属性での絞り込み方法として「完全一致」「含む」「始まる」を指定可能とする。
- 「含む」「始まる」が指定される場合、どちらか１つを選択可能とする。どちらも指定されない場合は「完全一致」とする。
- 「含む」・「始まる」はトグルボタンにて指定可能とする。(含む→始まる→完全一致)
- ソート・「含む」・「始まる」の各トグルボタンは各属性の名称と選択ボタンの間に配置する。
- URLのクエリ文字列はURLエンコード可能とし、画面上のラジオボタンでエンコード有無を切り替え可能とする。
- URLのフォーマットは以下の通り。
    - [ベースURL]/[部門ID]/[listTypes.path]/[viewPageのfilename]?FilterField1=[フィルタ条件1の列の内部ID]&FilterValue1=[フィルタ条件1の値]& ...
- 指定済み条件だけを1から連番でURLを生成。条件なしでは末尾の ? を付与しない。
- URLコピーボタンで、生成されたURLをコピーする。
- URLを開くボタンで生成されたURLを別タブで開く。
- コピー及び開いたURLはURL生成履歴として保持する。既に同じ内容が生成履歴にある場合は、既存の履歴を削除して登録する。
- 履歴は最新200件を保持し、超過分は古い順に削除。
- URL生成履歴から属性の選択状態を復元でき、条件を変更してURLを再生成できること。
- 各URL生成履歴に[URLをコピー][URLを開く]ボタンを設置する。
- 各URL生成履歴に✖︎ボタンを設置し、1件の履歴が削除可能(0.5秒かけてゆっくり消える)。削除前に確認メッセージを表示する。
- 現在の属性選択状態、履歴はlocalStorageへ保存し、ページ再表示時に復元する。
- localStorageへ保存した内容は、エクスポート・インポートが可能とする。
- インポートは10MB以下・履歴200件以下。
- localStorageキー
    - sharepoint-url-builder.v1: 現在の条件と履歴を保存
- キーボードショートカット
    - Enter: リンクを別タブで開く

## 外部通信・保存
- 外部ライブラリ、フォント、画像、APIは使用しません。CSPのconnect-src 'none'でも通信を制限しています。HTML/CSS/JSは同一フォルダから読み込みます。
- 「URLを開く」を押した場合のみ、別タブが指定先のSharePointへアクセスします。これも禁止したい場合はコピーのみ使用してください。
- ローカルファイルのlocalStorageはブラウザ設定、プロファイル、保存場所の変更、閲覧データ削除などの影響を受けます。同じ場所・同じEdgeプロファイルで利用し、移動前や定期的にエクスポートしてください。保存失敗は画面に表示されます。

## 設定方法(config.js)
- config.js の name が表示名です。listTypes の id は選択状態・履歴用の一意な識別子で、URLには使用しません。

| 設定 | 内容 | 例 |
| --- | --- | --- |
| baseUrls[0].id | ベースURL（1件） | https://intranet/sites/business |
| departments[].id | 部門の相対パス | quality |
| listTypes[].id | 配列内で一意の空でない識別子（保存・選択用） | regulations |
| listTypes[].path | 部門配下のリスト相対パス（必須） | Lists/Regulations |
| listTypes[].viewPage[ビューID].filename | ビューのページ相対パス（.aspx） | AllItems.aspx |
| filters[].id | SharePointの列の内部名 | RegulationNo |
| filters[].options[].id | 候補選択時のフィルタ値 | 001 |
| filters[].key | 保存用の一意キー | law |

- パスや候補値は未エンコードで指定してください。パスの / は階層区切りです。パス部分は常にエンコードされ、画面のラジオボタンはクエリの列内部名・値のエンコードだけを切り替えます。Lists を必要としない構成なら listTypes[].path から取り除いてください。
- 列内部名は表示名と異なる場合があります。実際の列設定に合わせて設定してください。候補のidはフィルタとして送る値であり、参照列のアイテムIDとは限りません。本版は指定された FilterFieldN / FilterValueN の形式専用です。参照列・複数選択など追加パラメータを必要とする列は実環境で確認してください。

### リスト・ビューの設定例

```js
{
  name: "法律管理",
  id: "regulations",
  path: "Lists/Regulations",
  viewPage: {
    all: { name: "すべて", filename: "AllItems.aspx" },
    pending: { name: "未対応", filename: "Pending.aspx" }
  },
  departmentIds: ["quality"],
  filterKeys: ["law"]
}
```

- 上記の未対応ビューでは、URLは `[ベースURL]/quality/Lists/Regulations/Pending.aspx` になります。
- `viewPage` 全体を省略すると `AllItems.aspx` を使用します。辞書形式では各ビューに `filename` が必要です。
- 移行時は、既存の `id` を維持したまま、その値を新しい `path` にコピーし、各ビューの `endpoint` を `filename` に変更してください。添付の設定にはこの変更を適用済みです。
- `path` は必須です。未指定時に `id` をURLのパスとして使うことはありません。同じpathを異なるidのリストで共有することは可能です。
- 保存済みの選択状態・履歴はidで対応付けます。pathやfilenameだけを変更すると、条件復元後の再生成URLに反映されます。履歴の「URLをコピー」「URLを開く」は記録済みのURLを使用します。
